## 1. 问题是什么

**现行规则**：挂 condition 的分支事件不建 Info，也不挂认知。写在五处：

| 位置 | 原文 |
|---|---|
| [CLAUDE.md](../CLAUDE.md) 第 96 行，「Event 图拓扑铁律」 | **分支事件（挂 condition）不建 Info/认知**——分支备线非既成事实，经 forms 键会跨支泄漏进小说取材 |
| [event-ideator/SKILL.md](../.claude/skills/event-ideator/SKILL.md) 第 147 行，§3 | **分支纪律**：挂 condition 的分支事件不提 Info/不产认知条目——分支备线非既成事实，建了会经 forms 键跨支泄漏进小说取材 |
| 同上，第 181 行，I3 条目格式 | 分支事件（挂 condition）不出本类条目 |
| 同上，第 227 行，§6 盘点口径第 4 条 | **分支事件不建**：同 §3 分支纪律（挂 condition 的事件一律零增量）；Choice 兑现事件（选项本体）同理；分支段重盘以**主支确定**为前提 |
| [suggest-consumer/SKILL.md](../.claude/skills/suggest-consumer/SKILL.md) 第 66 行，Cognition 机器项 | **锚事件 condition 检查**——establishes 与 forms 的锚事件挂 condition → 报错退回 |

最后一处是机器门禁：走共识、定稿、建议 JSON 这条链写图时，锚在分支事件上的认知会被拦下。Schema 文档（`00_init/Schema/`）和 Harness 里没有这条规则。

**规则的理由**：跑团端判断「某人此刻知不知道」只看时间。认知锚在一个事件上，从这个事件的时间起、在任何一节里都算有效。玩家没走那条支线，那条支线里得知的事却会被算成知道。

**为什么现在成了问题**：2026-11-25 的新模型让固有 Info 进了认知层，披露审验两侧对称——一条固有 Info 只要有人持认知，宿主自述也受控，没有认知的在场者面前不能点破。于是出现了一类新矛盾：

- 两个人只在支线戏里见面，按规则不能建认知；
- 其中一个人的固有事实已经被别人建了认知，于是受审验；
- 这场支线戏里，他不能向对方点破自己的这条事实。

戏本身还能演，只是那句自我介绍会被拦。受影响的是「当场认识」这种最普通的场面。

结论：

- 这五处现在放开也不会跨线——持有者锚之后只在自己的支线里出场，06-30 之后图上还没有事件。

**比这五处大的隐患**：陈默在三条支线里各会得知不同的事。按现在只看时间的判断，他在一条支线里得知的事，在另外两条支线的节里也算他知道。第三章一拆章、补认知就会整体出现。这一条跟上面的规则放不放开无关：只要支线事件上开始挂认知（或者陈默本人在支线里形成认知），就需要跑团端认分支。

## 3. 三种处理方式

### A. 规则不动

- **做法**：不建。只在支线戏里见面的人，想让他「知道」，有两条路：故事上本来开篇前就认识的，建前史认知（无 forms，任何支线都成立）；否则不建，那场戏里不能点破那条事实，其余照演。
- **要改什么**：不用改。
- **代价**：「当场认识」表达不了。第三章拆章之前，这个矛盾会随着更多固有 Info 建起认知而变多。
- **和现有流程的关系**：event-ideator §6 已经写了「分支段重盘以主支确定为前提」，也就是这个问题本来就打算等分支结构定了再回头处理。

### B. 放开认知，但限制持有者

- **规则拟改成**：分支事件（挂 condition）不建 Info。认知可以锚在分支事件上，但持有者必须只在这条支线出场——锚之后不出现在别的支线或主线事件里；多条支线都在的人（陈默）不锚。
- **要改什么**：第 1 节表里的五处。其中 suggest-consumer 的机器项要从「锚事件挂 condition 就报错」改成「锚事件挂 condition、且持有者在锚之后出现在别线或主线上才报错」，需要在 skill 里加一条查询。
- **解决了什么**：五处可以按「当场认识」如实建。
- **代价与风险**：限制靠人守。日后新增一个让持有者离开这条支线的事件，这条认知就开始跨线，而没有任何东西会报错，除非再给 Dashboard 体检加一项。
- **没解决**：陈默的跨线。

### C. 全面放开，同时让跑团端认分支

- **规则拟改成**：分支事件与主线事件同等待遇。
- **要改什么**：
  - Harness 的 `tabletop-dialoguer`：锚事件带 condition 时，只有本节里有同一 condition 的事件才让它有效。节属于哪条支线，从节内事件的 condition 推出。还要补单测和夹具。
  - 汇合之后的节（只有主线事件）判断不了属于哪条支线，需要故事结构先定：各支线各自成节到章末，或者设一个汇合事件，或者给 Section 加支线字段。最后一种是 Schema 变更。
  - 规则文档按新口径改。
- **解决了什么**：五处都能建，陈默的跨线也一并解决。第三章进节之前本来就需要它。
- **代价**：是一次 Harness 改动加一个第三章的结构决策。另一路会话在改 `tabletop-dialoguer`，要错开。

## 4. 建议

规则现在不动，按 A 走。理由是规则的理由仍然成立：跑团端只看时间，一放开，第三章给陈默建认知时就会跨线。

#1、#2 两条按故事来定：

- 故事上开篇前就认识：建前史认知，现在就能执行。林梦玩 cos、要打理假发，认识 Tony 说得通。苏晓禾认识季棠这一条要你判断。
- 故事上是到了那场戏才认识：先放着，留到第三章拆章时处理。

第三章拆章时做 C，至少把跑团端认分支做掉，到时候再决定要不要全面放开。B 只适合不想等、又想把这两条按「当场认识」建的情况。
