# Info 盘点方法论

> 存量事件 → Info/认知 的抽取流程与判例库。适用场景：全量盘点、按章批次盘点、主支确定后的分支段重盘、任意存量知情补全。模型契约本身见 [00_init/Schema/剧情/](../00_init/Schema/剧情/)（Info/Cognition/边定义），本文只管「怎么抽」。

## 方法论：A 逐事件扫雷（事件驱动）

按 `start_time` 升序逐事件过堂，每个事件回答「该事件使什么事实成立（0~N 条）」→ 每条事实当场判认知分布（谁以什么态度知道、forms 锚哪个事件）→ 后续事件再现同一事实时回补 establishes 承载边。

选择依据（三方法对照试验，样张见 `2026-11-19_Info盘点ch1_方法{A,B,C}_草稿.md`）：事实侧三法高度收敛，A 的事件覆盖有结构保证（逐个过堂不可能漏事件）、逐行留痕可审计性最佳、成本最低；B（事实清单先行）归并最干净、C（角色认知时间线）认知最完整，均可在 A 框架内借用其视角补强（认知判定时过一遍角色侧、归并时参考事实簇），不单独立流程。

## 执行口径

1. **穿越后主语**：2024-05-31 18:00（穿越）起身体行为获得的认知，主语一律记陆择；陈默原主灵魂状态图上不表达。
2. **远程知晓 forms 锚**＝内容可得的源头事件（发布/直播/告知事件），不锚下游行为事件。
3. **疑似知情者按叙事意图推断补建**，条目 reason 标注「推断」——图上无载体但叙事意图明显时补，杜绝系统性少计。
4. **分支事件不建**：挂 `Event.condition`（choice 表达式）的事件一律零增量——分支备线是可能性空间非既成事实；分支内 Info/认知会经 novelist 圈定（forms 键不过滤 condition）跨支泄漏。Choice 兑现事件（选项本体）同理。分支段的抽取以**主支确定**为前提（见文末重盘窗口）。
5. **从严口径（最高优先）**：只立有**持续叙事意义**的事实——身份/关系/资源/知情面的持久变化。过程性/过渡性事实（战绩起伏/单次冲突/方案文档/邀约悬置/日常互动）默认不立，宁漏勿滥；拿不准列裁决点附「从严建议不立」。此口径为实战教训（ch2 撤回 8 条过程性条目，档见 `2026-11-19_Info盘点ch0ch2_共识.md` §一/§二）。

## 流程步骤

1. **圈定范围**（章/时间窗/游离段），查图取事件全量明细：id/title/start_time/description/involved/occurs_at/**condition**（condition 决定分支处置，必须先查：`MATCH (e:Event) WHERE e.start_time >= '…' RETURN e.condition, count(*)` 一眼看分布）。
2. **查基线**：既有 Info 与认知分布（`MATCH (i:Info)<-[:establishes]-(e) RETURN i.title, collect(e.title)`；`MATCH (ch)-[:has_cognition]->(c)-[:about]->(i) MATCH (ev)-[:forms]->(c) RETURN ch.name, i.title, c.type, ev.title`）——只记补条目（新承载边/新知情者/态度转变改写），不重建。
3. **建事实登记表**（文档内可见的表格：事实 → 承载事件集 → 已登记认知）——贯穿维护，防两个实测陷阱（见下）。
4. **逐事件过堂**，三分记录：**产出**（事实+认知）/ **零增量**（无认知增量）/ **从严不立**（有素材但按口径 5 不立——留痕供重盘）。
5. **汇总**：新 Info（title 中性事实句/kl/establishes 源/认知分布）+ 补条目 + 裁决点清单（附推荐）。
6. **用户拍板裁决点** → 共识文档（`<日期>_Info盘点<范围>_共识.md`，裁决记录节随附）→ **suggest-consumer** 消费（严检/lint/执行确认门/单事务落图/读回验证）。
7. **终验**：无孤 Info（全部 ≥1 establishes）、无残认知（forms≥1 且 about 齐）、(Character,Info) 零并存、认知 type 分布合理。

## 已知陷阱与防补

- **锚定陷阱**：顺流处理时倾向把知情者 forms 锚到当前事件——先问「他在此事件**之前**是否已知」，更早形成的认知锚更早的事件（判例：林梦对陈默实力的认知锚前史代练单，非暴走局；王昊/李想对提升方案的认知锚白板讲解，非方案成文）。
- **漏回补**：同一事实跨 5+ 事件再现时靠记忆必漏——登记表的存在就是防这个。
- **「不硬凑」纪律**：无认知增量的事件记零增量，别为覆盖率硬产条目；数字细节/氛围归 Event.description，不另立 Info。
- **双边关系事实**：已有 relation 边的不重复建 Info；一次性冲突+认知分布有意义的可立 Info（判例：陈默与江烈试训起冲突）。
- **固有 vs 事件性**（Lore/Info 分界）：因事件成立且知晓分布有叙事意义 → Info（判例：陆择死于车祸、林梦喜欢陈默，均从 Lore 转出）；纯人设底色宿主自知 → Lore（判例：沈暮雪「外冷内细」保留）。知晓分布是分界的实质判据——Lore 装不下「谁知道」。

## 判例库

| 判例 | 裁决 | 出处 |
|---|---|---|
| 当事人对自己情感/处境的认知 type | KNOWS（最直白，态度层如嘴硬不另设） | 林梦×「林梦喜欢陈默」 |
| 模糊担忧 ≠ 对强命题起疑 | 角色察觉的是**更弱的替代命题**（「最近心情不好」）而非对 Info 命题本身起疑时，用 BELIEVES+弱命题 title，不用 SUSPECTS——SUSPECTS 保留给「对 Info 命题趋向为真但无替代命题」 | 陈念×「陈默意图跳江轻生」= BELIEVES「陈默最近心情不好」 |
| 一次性冲突 vs relation 边 | Info 管辖（知晓分布丢失不可接受） | 江烈冲突条 |
| 固有志向经告知进入故事 | Info（陆择知情有叙事意义，Lore 无处记录跨角色知晓） | 沈暮雪目标 |
| 归因偏差 BELIEVES（甩锅类） | 不建——从严口径下偏差条目从少 | 王昊×连败 |
| 战绩起伏/方案/邀约悬置/单次游玩 | 不立（过程性） | ch2 撤回 8 条 |
| 多事件同事实 | 并列 establishes（一条 Info 多承载边） | 技术顶尖×4 承载、拮据×2 承载 |
| 相亲/安排类三方在场事实 | 三人均锚同一事件 | 相亲局条 |
| 通知类事件缺位时的 forms | 推断锚：涉己电话或内容源头事件，标注推断 | 踢人决定 |
| 聚合态事实（多邀悬置） | 不立（从严）；若立则聚合单条 | 三份邀约撤回 |
| 停播/入队兑现等分支内事实 | 不建，主支确定后重盘 | 游离1 判读 |
| kl 定档 | 1=长效背景（车祸/技术/头条）/ 2=参与细节（出资/冲突）/ 3=深层热点快衰（轻生念头/好感） | 全量 |
| 穿越前存量认知主语 | 不追溯改写（存量维持）；穿越后新认知一律陆择 | 主语裁决 |
