## 5. AppearanceStyle.appearance 废除可行性论证（用户提议：考虑整体去掉）

**现状**：20 条节点，仅 3 条非空（苏晓禾/江烈/1 条未命名占位）。字段定义为「自由文本：综合气质、身高、整体观感」——三个职责都另有载体：
- 综合气质 → Character.vibe（fc31327 已定职责「人物调性的单一事实源」）
- 身高 → height_cm（结构化，111-12 已迁移数字，仅 2 条双存且无重叠）
- 整体观感/体型描述 → body_type / shape_language 结构化标签已覆盖主干

**3 条非空拆解**：
- 苏晓禾：「匀称健美的运动型身材，长期锻炼带来的轻盈体态，肩颈线条利落，四肢修长有肌肉线条但不过分」——纯客观体型描述，body_type「匀称健美」可承载，余句是体型细节。无气质词。
- 江烈：「精瘦利落的少年感身形，肩背挺直，体量感低，肩背挺直，下颌线条干净利落，面部带常年高强度训练熬出的淡淡倦色」——同上纯客观体型+面相，body_type/shape_language 承载主干。
- 未命名占位（name=null）：纯占位残留，直接删属性。

**消费方影响**（grep 实证）：char-design-sheet SKILL.md:68/76、char-prompt-assembler SKILL.md:57/68 引用 appearance 字段——但 prompt-assembler 的组装规则（:68）写明「**height_cm 数值优先，缺失取 appearance 文本**」——废除后身高取值链退化为 height_cm 单源，20 条中 20 条都有 height_cm（**无一缺失**）。另组装段⑤「气质神态 ← Character.vibe + appearance 气质部分」——废除后气质单源 Character.vibe，正符合 fc31327 的「气质单一事实源」原则。体型细节（「肩颈线条利落」）在 body_type/shape_language 标签粒度不够时确实有损——但 3 条存量里这种细粒度描述有限，可把细粒度体型短语并入 vibe（vibe 规范允许「身材/质感」通感表达）。

**结论**：**可废除**。条件是 3 条存量的细粒度体型句先并入 Character.vibe（按 vibe 提纯规范重写，非机械搬），然后 REMOVE appearance 全量。触发条件与 #1-#4 相同批次执行。

**处置**：
- 存量搬迁：苏晓禾/江烈 2 条非占位的细粒度体型句，按 vibe 生成规范并入各自 Character.vibe（提纯重写——需要出小样给你过目后全量，复用 11-06 speech_style 的「小样→认可→全量」流程）；未命名占位直接删。
- 图：`MATCH (a:appearanceStyle) REMOVE a.appearance`。
- Schema 觚色美术.md AppearanceStyle 字段表删 appearance 行，节点开头「定义角色的固定外貌（脸、体型、 外貌…）」同步改写。
- 写方：char-design-sheet:68 JSON 模板删 appearance 键；char-prompt-assembler:57/68 组装段删「缺失取 appearance 文面」回退链与「appearance 气质部分」。

**验收**：图 0 检出；char-design-sheet 重建一版设计图 dry-run 通过（身高单源 height_cm）。

## 7. 判定不冗余清单（免复查）

| 载体 | 判定理由 |
|---|---|
| `IllusDesign.display_scale`（33 条） | 「写时物化、读时零推理」的刻意决策：上游 height_cm/REF_HEIGHT 推算结果在写边时物化进节点，避免运行时每帧反查图——与 appears_as 版本判定同一模式 |
| `relation.illus`、`appears_as.detail` | 同上，挂边物化模式：本体造型锚/着装语境写时落边，读方直读 |
| `Scene.name` 时段后缀 vs time_of_day | name 不锚定目录/键/文件（锚 hexid），纯人读注记，无漂移风险 |
| `Hook/Lore.content` | 已降级「非必要不填」，存量仅 1 条；title 即事实原则已立 |
| `SubEvent.description`（85 条） | stager 演出规划素材、novelist 取材消费，层级职责清晰，非双写 |
| `Section.summary` vs StoryArc.description | 戏剧职责（本节干什么）vs 线主旨（这条线表达什么），不同层不同消费者 |
| `LineAudio.tts_text` vs text | 刻意双载体：TTS 变体禁止写回 text，有明确禁令与用途差（标点/停顿修饰） |
| `LanguageStyle` 旧四字段 | 已清干净（图上仅存 name/id/status/speech_style 四键） |
| `Event.description` vs title | title=一句标题，description=数字细节/氛围摘句，粒度职责不同 |
