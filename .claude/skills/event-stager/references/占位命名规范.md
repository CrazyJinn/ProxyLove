# 占位节点命名规范（stager §3 占位物化时对照）

> 占位节点的 name 是**叙事侧决策的载体**（哪个房间、哪套衣服），也是后续被消化时的
> 第一需求上下文——命名必须**见名知义**且**不与既有节点重名**。以下模式全部从图上
> 实存节点归纳。

## Spot（空间缺口）

格式：`<Location名>-<区域名>`；完全未细分的空间用后缀 `-未细分`。

- 图上实存：`服装店-未细分`、`灵魂夹缝-未细分`
- 区域名取功能分区词（大厅 / 门口 / 厨房餐区 / 床铺区…），不用编号或方位词
  （「东侧」没有叙事含义，「床铺区」有）
- **room-dsl 对齐**：Spot 的 name 即 room.yml 里的房间名——后续细化 3D 布局时
  直接以此名建房间，改名会造成 dsl 与图漂移，故占位期就要定准
- kind 一律 `'zone'`（default 已废止，仅存量）

## Scene（机位缺口）

格式：`<语境地名>-<子空间或机位>`，可选第三段 `-<版本/时段>`。

- 图上实存：`八楼出租屋-床铺区`、`长江大桥-护栏段`、`街角咖啡店-点餐台`、
  `星耀电竞基地-门口`、`康复中心-训练大厅`
- 带版本后缀（同机位跨时段变化时才用）：`八楼出租屋-电脑桌直播位-更新设备前`
- 单点地标可省第二段：`火锅店`、`灵魂夹缝`
- scene_type 现存全为 `dialogue`；新机位无明确他型需求时默认 dialogue

## CostumeStyle（服装套缺口）

格式：`<角色名>-<套装短描述>`。

- 图上实存：`沈暮雪-墨绿色连衣裙`、`Tony-前卫手艺人着装`
- 套装短描述 = 一眼可想象的关键件（颜色+品类 / 风格词），不超过 ~8 字；
  outfit_style 填风格标签（分号分隔，如 `优雅;性感`）
- **先查图后命名**：同角色已有 N 套时，新占位名必须与既有套可区分
  （`沈暮雪-墨绿色连衣裙` 已存在就不能再叫 `沈暮雪-绿裙`——消化方
  会当成两套）

## IllusDesign（形象版本缺口）

**不取 name**（图上实存 IllusDesign 的 name 几乎全为 null）——身份由
`outfit_for` 挂靠的 CostumeStyle + adaptation_notes 共同表达：

- adaptation_notes 写**该版本与基线的差异与气质**，图上实存样例：
  `自信期气质：昂首挺胸，站姿挺拔舒展，肩背舒展打开，眼神坚定、神态从容，居家放松而不瘫懒`
- 版本差异点（剪发前后 / 自信期前后 / 换季着装）必须落在 notes 首句，
  让消化方不读上下文就知道这一版「变在哪」

## 命名自检（落建议 JSON 前）

1. **查重**：`MATCH (n:Spot|Scene|CostumeStyle) WHERE n.name = '<拟名>' RETURN n`——
   命中即换名（占位与真身重名 = 图上两节点打架）；
2. **见名知义**：消化方只看 name + 图位置就懂需求，不需要再问——
   「未细分」「更新设备前」这类词允许，无信息的「新场景 2」不允许；
3. **不改既有真身的名**：占位命名只作用于新建节点；既有节点名属于其生产
   链，改名走 dashboard 编辑（会触发级联语义），stager 不碰。
