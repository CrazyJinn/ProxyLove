## 细化事件（SubEvent）

> 字段全集以本表为准；skill 写入前 Read 本节，不凭记忆写字段。

最小粒度：父事件（Event）在机位层的演出物化——到场/离开/换区/换装等演出段。一个 Event 可细化出多个 sub，一个 sub 只属一个父（存量分布 0~4 sub/事件；无 sub 事件=显式工作缺口，交 event-stager 补细化）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `<父事件title> · <叙事短名>`——短名 = 该演出段的叙事副题，贴切为先、不拘字数（如 `塞满唠叨`、`一个人的游戏`）；**不用机位名**（机位信息只走 anchored_at 边，Scene 改名零漂移） |
| time | 时间 | string(datetime) | 是 | 继承父事件或时间插值 |
| description | 描述 | string | 否 | 演出内容——节拍级 2~4 分句（撰写契约见下节） |

- SubEvent **无** status / type / ending_kind / condition / involved / occurs_at——叙事身份（时间、人物、地点、因果、分支）全部在父 Event 层；sub 只承载 `anchored_at→Scene`、`appears_as→IllusDesign` 与 `reveals→Hook` 三边。
- **时间轴查询只碰 Event**（label 隔离——SubEvent 不干扰 Event 时间轴/时间窗查询）。
- 删父 Event 必须连带删其全部 sub。

### description 撰写契约（唯一权威——event-stager 生成、novelist 消费均以本节为准）

sub 是**结构决策层，不是初稿层**：novelist 拿它知道「该演哪几个节拍、谁主导」，但不知道「具体怎么演」。写得细 = 越权替 novelist 排练（细节含物理瑕疵，novelist 被迫消化）；压得简 = 节拍链断裂、novelist 无锚可依（单句版效果不佳）。

**description**：**2~4 个分句**（分号分隔），每分句一个节拍——「谁 + 做了什么」并**点明互动方向**（谁主动、谁反应、对视/先后/呼应等）。

| 写 | 不写 |
|---|---|
| 每分句一个节拍（动作 + 互动方向） | 台词、语气词（novelist 从节拍自拟） |
| 必要的因果衔接（**仅限同事件内前后 sub**） | 道具与环境细节、具体数字（novelist 即兴域） |
| | 情绪标签/基调词（情绪由节拍的动作与互动方向自带） |
| | 站位/镜头设计（立绘与分镜层的事） |
| | 字段头（「动作：」「基调：」等一律不写） |
| | 机位名（只走 anchored_at 边） |
| | 参与人名单（sub 的参与角色由父 Event 的 `involved` 边唯一承载——description 写名单即第二套事实，必与图漂移） |
| | 跨事件相对时间词（「同日下午」「当晚」——跨事件时序由 leads_to 边与 Event.time 承载，时间唯一承载是 Event.time） |

sub 写成微剧本的代价：道具台词进了图却不进 novelist 取材指纹（sub 不受 stale 保护，两层无感漂移）；改一句台词要动图→小说→ink 三层。

正例：`开局操作生涩，客户旁观质疑；中段肌肉记忆接通，陆择带队翻盘取胜；客户求加钱，群友哗然`
反例：`转账记录翻到底全是转给温蔓青（累计六万六千六百六十六、零回复）；他停了几秒没笑出来`（具体数字+神态，微剧本形态）、`桥面摆满陌生人自发买来的奶茶与外卖，如无声祭奠`（镜头设计与文学修辞，novelist 即兴域）
