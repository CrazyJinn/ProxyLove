## 信息（Info）

> 字段全集以本表为准；skill 写入前 Read 本文件，不凭记忆写字段。

最小粒度：一条**事实**。与 Event 对仗：**Event 记「发生」，Info 记「事实」**——Event = 需要在故事时间轴上**被演出**、直接推进剧情的事（有参与者、发生即改变局面，可细化演出 `refines → SubEvent`）；Info = 不需要演出来的事实。

### 两类 Info（按挂靠边分，互斥）

| 类 | 挂靠 | 含义 | title 契约 |
|---|---|---|---|
| **固有 Info** | `(Character\|Location) ─has_info→ Info`（≥1 条），0 条 establishes | **在故事开始时为真**的事实（不承诺恒为真——后续被终止事件翻转的，按终止事件推导现状）：身份、职业、性格、身世、地点属性 | **「维度：值」**——不写宿主名（主语由 has_info 宿主承载），一条只写一个事实。例：`职业：理发师`、`职务：星耀一队队长`、`月租：一千八，按季付` |
| **事件 Info** | `Event ─establishes→ Info`（恰 1 条），0 条 has_info | **故事内某个动作使之成立**的事实（如「视频火了」「陈默加入星耀二队」） | 带主语的完整事实句。例：`陈默加入星耀二队`、`沈暮雪辞职` |

- **判定测试——何时开始为真**：在故事开始时为真 → 固有 Info，挂宿主；故事内某动作使之成立 → 事件 Info。判据是「**使之成立**」，不是「使之得知」——某人在某事件得知一条固有事实，归 Cognition 的 `forms`，不改变 Info 的类别（同一条「职业：护理师」，苏晓禾开篇前就知道，陈默在初遇那场戏才知道）。
- 一件事要不要在时间轴上「演出来」？要 → Event。一件事的数字细节、氛围摘句归 `Event.description`，**不另立**（防复述）；角色间双边关系事实优先 `relation` 边承载（见 [../角色美术/边.md](../角色美术/边.md)）。
- **挂靠不变式**：每条 Info **恰有一种**挂靠。两种都没有 = 孤儿；两种都有 = 混轴——均为结构错误（dashboard 体检兜查）。
- **开篇前的事实不建前史事件**：「A 认识 B」「B 是富家公子」这类在故事开始时为真的事实直接建固有 Info，不为它编一个成立事件。前史事件只在真要演回忆（闪回）时才建。
- **Info 无出边**，只被指向：`has_info`（固有宿主）、`establishes`（事件成立）、`about`（认知指向）。边定义见 [边.md](边.md)。

### 知晓分布（认知层）

- **宿主默认自知**：宿主不为自己名下的固有 Info 建认知。
- 其他任何人对任一类 Info 的知晓，一律由 Cognition 层显式承载：`Character ─has_cognition→ Cognition ─about→ Info` + `Event ─forms→ Cognition`（何时经何事件得知）。**没有 forms = 开篇前就知道（前史认知），只能指向固有 Info**。契约见 [Cognition.md](Cognition.md)。「参与即知情」已废止，`involved` 不推导任何知情。
- **披露审验**：一条固有 Info **一旦有人持认知**，就进入封闭世界管理——说话人与听者两侧都按「知道什么」判，**宿主自述也不例外**。剧情上要让某人得知一条固有事实（包括当事人自己说出来），在设计期建 Cognition，`forms` 锚在说出口的那场戏；跑团不得临场创造知情者。

### description 分界契约（散文可读 ≠ 事实已承载）

Event.description 里的信息要素对认知集投放、同义查重、freshness 全部不可见——散文提过不等于图已承载。description 只记**行为与名义**（发生了什么、以什么名义/由头进行），信息要素按内容分流上移：

- **事实成立**（这使什么成为持久事实）→ 事件 Info + establishes
- **知晓变化**（谁从此知道了）→ Cognition + forms
- **意图/误信**（角色以为什么、想干什么）→ 有后续叙事意义则 Cognition（BELIEVES+title，forms 锚来源事件）；纯氛围留 description
- **悬置意向**（未兑现的邀约/计划）→ 兑现前 description 弱承载；兑现事件落地后回看回补
- **过程性/数字/氛围** → description（从严豁免，不另立）
- **承载二择一铁则**：改 Event.description 剥离信息要素前，先查该事实有无 Info/Cognition 承接——无承接且非豁免类，先建承接再剥；两头都不在 = 事实从图世界抹除。

### 成立锚唯一（establishes 1:N）

事件 Info 恰一条 `establishes` 入边，锚**事实实际成立**的事件——「局的起点」已使事实成立（设局邀约即安排成立）则锚起点事件；「表态悬置」在兑现前事实未成立（邀约≠加入）则锚兑现事件（悬置期 description 弱承载，兑现事件落地后回看回补）。**揭示时刻不挂 establishes**——到场揭底/告知/围观是知晓域事件，归 Cognition（forms），不承载成立。

- title/content 为干净的事实陈述，**禁备忘/推导文字**（日期注记、编号引用推导、归属标注）；变更历史不落图。

**knowledge_level 枚举**（只服务 freshness 半衰期档位与暴露节奏（消费方 tabletop/dialoguer），**不影响认知集投放**——知晓分布由 Cognition 层承载）：

- `1`：表层——新闻报道、警方通报等公开信息
- `2`：参与层——需要阅读聊天记录、转账记录等细节才能了解的信息
- `3`：深层——需要综合推断或获取非公开信息才能理解的隐性事实

## 字段

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | 事件 Info：`沈暮雪辞职`（拿掉本节点，这条信息在图上无处可寻——是则 title 合格承载）。固有 Info：`职业：理发师`（不写宿主名，一条一事）。均禁备忘/推导/归属标注 |
| content | 内容 | string | 否 | **默认不填**。仅当「图上其他实体无载体」的增量（如定义式 `弱者＝认真对待感情却伤痕累累的人`）；不做 title 的扩写、不举剧情例子 |
| knowledge_level | 知识层 | enum | 是 | `1`（亦为 freshness 半衰期档位：1→h12 / 2→h6 / 3→h3） |

---

> **节点一律 `Info` 标签**；固有 / 事件按挂靠边判别。
