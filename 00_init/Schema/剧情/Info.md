## 信息（Info）与设定（Lore）——共同背景

> 字段全集以本表为准；skill 写入前 Read 本文件，不凭记忆写字段。

最小粒度：一条**事件性事实**（Info）或一条**固有设定**（Lore）。与 Event 对仗：**Event 记「发生」，Info 记「事实」，Lore 记「固有」**。

- **Event = 行为、事件**——需要在故事时间轴上**被演出**、直接推进剧情的事：有参与者、发生即改变局面，可细化演出（`refines → SubEvent` 落机位）。
- **Info = 事件性事实**——因事件而成立、按「谁知道」管理的世界状态（如「视频火了」「陈默被温蔓青分手」）。成立与揭示时刻不落图：事实成立由 `Event ─establishes→ Info` 承载（成立轴），知晓分布由 Cognition 层显式承载（见 [Cognition.md](Cognition.md)），何时向读者交付由写作层（tabletop/dialoguer）裁量。
- **Lore = 固有设定**——角色/地点的固有事实（人设底色、世界观规则、背景前史）。无时间轴位置，反复以侧面折射方式被消费；**暴露节奏由写作层遗忘曲线算法管制**（freshness，消费方 tabletop/dialoguer），图上不计划。
- **判定测试**：这个内容要不要在时间轴上「演出来」？要 → Event；因事件成立的认知、且不同角色知晓状态有分布意义 → Info；角色/地点固有属性 → Lore。一件事的数字细节、氛围摘句归 `Event.description`，**不另立**（防复述）；角色间双边关系事实优先 `relation` 边承载（见 [../角色美术/边.md](../角色美术/边.md)）。
- **description 分界契约（散文可读 ≠ 事实已承载）**：Event.description 里的信息要素对认知集投放、同义查重、freshness 全部不可见——散文提过不等于图已承载。description 只记**行为与名义**（发生了什么、以什么名义/由头进行），信息要素按内容分流上移：
  - **事实成立**（这使什么成为持久事实）→ Info + establishes
  - **知晓变化**（谁从此知道了）→ Cognition + forms
  - **意图/误信**（角色以为什么、想干什么）→ 有后续叙事意义则 Cognition（BELIEVES+title，forms 锚来源事件）；纯氛围留 description
  - **悬置意向**（未兑现的邀约/计划）→ 兑现前 description 弱承载；兑现事件落地后回看回补
  - **过程性/数字/氛围** → description（从严豁免，不另立）
  - **承载二择一铁则**：改 Event.description 剥离信息要素前，先查该事实有无 Info/Cognition 承接——无承接且非豁免类，先建承接再剥；两头都不在 = 事实从图世界抹除。
- **成立锚唯一（establishes 1:N）**：一条 Info 恰一条 `establishes` 入边，锚**事实实际成立**的事件——「局的起点」已使事实成立（设局邀约即安排成立）则锚起点事件；「表态悬置」在兑现前事实未成立（邀约≠加入）则锚兑现事件（悬置期 description 弱承载，兑现事件落地后回看回补）。**揭示时刻不挂 establishes**——到场揭底/告知/围观是知晓域事件，归 Cognition（forms），不承载成立。
- **挂靠（Info/Lore 无出边，只被指向）**：
  - **Info 成立轴**：`Event ─establishes→ Info`（该事件使事实成立并进入故事，如 陈念上门探望→「陈默被温蔓青分手」）。**由 event-ideator 产**——提案事件时自问「**这个事件使什么事实成立（产生了什么信息要素）**」，只产 Info 本体 + 成立承载事件（默认本事件；固有前史事实建前史事件承载）。**知晓分布另由 Cognition 层显式承载**（谁、什么态度、经由哪个事件知道——见 [Cognition.md](Cognition.md)）；「参与即知情」已废止，involved 不推导知情。
  - **Lore 宿主**：`(Character|Location) ─has_info→ Lore`（谁/何地的固有设定，如 陆择→「陆择是海王」）。构图期人工拍板；宿主默认知晓自己名下的 Lore，跨角色知晓不建边（需要时另议）。
  - title/content 为干净的事实陈述，**禁备忘/推导文字**（日期注记、编号引用推导、归属标注）；变更历史不落图。

**knowledge_level 枚举**（只服务 freshness 半衰期档位与暴露节奏（消费方 tabletop/dialoguer），**不影响认知集投放**——知晓分布由 Cognition 层承载）：
- `1`：表层——新闻报道、警方通报等公开信息
- `2`：参与层——需要阅读聊天记录、转账记录等细节才能了解的信息
- `3`：深层——需要综合推断或获取非公开信息才能理解的隐性事实

## 信息（Info）

事件性事实：因事件而成立、按「谁知道」管理的世界状态。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `沈暮雪辞职`。title 即事实本体：干净的事实陈述，禁备忘/推导/归属标注；检验：拿掉本节点，这条信息在图上无处可寻——是则 title 合格承载 |
| content | 内容 | string | 否 | **默认不填**。仅当「图上其他实体无载体」的增量（如定义式 `弱者＝认真对待感情却伤痕累累的人`）；不做 title 的扩写、不举剧情例子 |
| knowledge_level | 知识层 | enum | 是 | `1` |
