## 角色（Character）

> 字段全集以本表为准；skill 写入前 Read 本节，不凭记忆写字段。

最小粒度：每个有名字的真实人物。角色实体的一站式定义（基础属性 + vibe 调性）；挂靠事件（`involved`）与固有设定（`has_info`）的边定义见 [../剧情/边.md](../剧情/边.md)。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 姓名 | string | 是 | `陆择` |
| gender | 性别 | enum | 否 | `男` / `女` |
| birth_year | 出生年份 | int | 否 | `2003` |
| ref_image_path | 参考图路径 | string | 否 | `06_角色美术/<char_id>/参考图.jpg`（hexid 段；dashboard 上传时 SET，char-design-sheet 探测读属性） |
| priority | 优先级 | enum | 否 | `P0` / `P1` / `P2`：制作优先级，P0 最优先（分组即本字段值，以图上 Character 现状为准） |
| vibe | 设计氛围 | string | 否 | 人物调性的单一事实源（一段 2~3 句）。性格内核→感官调性（含配色方向）；不写生理外貌（归 AppearanceStyle）、身份事实（归 Lore）、剧情因果（归 Event）、台词样例。四问与总则见 [Schema总览.md](../Schema总览.md)「属性撰写总则」；下文「vibe 生成规范」为展开 |

**vibe 生成规范**（核心思想：把人物的性格内核，翻译成感官可感的调性——不是在描述这个角色，而是在给这个角色「定调」）：

1. **源头是性格，落点是感官**——输入是「他骨子里是什么样的人」，输出必须是通感表达：这段性格看起来是什么颜色、摸起来是什么质感、走进房间时空气怎么变。性格直述（「外冷内热」）不是 vibe，翻译完成（「冷调象牙白与深酒红的克制，暗金点睛」）才是。
2. **一段文本服务三个创作端**——造型师选面料配色、声线师定音色气质、写手定出场氛围，读同一段话取到的味道必须一致。写前自问：这三个人拿到这段话，各自知道往哪个方向使劲吗？
3. **只写恒定调性，不写任何会变的东西**——生理外貌（发色/瞳色/肤色/体型）归 AppearanceStyle 结构化字段；设定事实（职业/家世/经历/能力）归 Lore；剧情因果归 Event。检验法：**把这段话放在第一章和最后一章，它都还成立吗？** 成立才是 vibe；会过时的说明写进事实了。

正例：`灰扑扑的低饱和感：把自己排在最后的怯，小心翼翼讨好的软；旧毛衣般的旧、蒙尘的钝感`；反例：`手艺人健谈热心（Tony 原形象存档）`（备忘标注不落属性）、`黑色长发瓜子脸`（生理外貌归 AppearanceStyle）。
