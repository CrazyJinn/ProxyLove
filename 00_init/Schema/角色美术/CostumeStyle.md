## 着装特征（CostumeStyle）

> 字段全集以本表为准；skill 写入前 Read 本节，不凭记忆写字段。

每套装扮一个节点。定义角色的具体着装（衣物、配饰、材质等）。创建后即 `status=1`（已完成，无审批）。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `着装名称`：简短描述（如 `工作服`）——**纯着装名，禁内嵌角色名前缀**（不锚定目录/键，仅展示） |
| vibe | 着装调性 | string | 否 | 这套着装的整体调性一句话（与其他节点 vibe 语义一致）——只写装束自身的调性；人物姿态/气质/神态不写（随人设走，非单套着装属性）。正例：`干练利落的职场正式`；反例：`姿态挺拔沉稳克制`（人物姿态） |
| garment | 服装 | string | 否 | 服装款式/颜色统一记录处。合成组合（顺序固定；多件半角 `;` 分隔）：每件含必选（材质+颜色+类型）与可选（领型/滚边/层次/剪裁/穿法/质感氛围等，不宜过多）：`棉白衬衫;黑色丝袜`——只写衣物。正例：`未漂白亚麻粗布长袍(粗纺纹理、交领宽袖、前襟敞开不系束)`（穿法入可选维度）；反例：`…;刚洗完澡，头发有点微湿`（演出状态不是衣物） |
| footwear | 鞋类 | string | 否 | 标签 |
| accessory_type | 配饰类型 | string | 否 | 标签（可多选）；具体样式用自定义标签值补充 |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**：`0` 待设计 → `1` 已完成

> 无审批流程：着装内容生成后即 `status=1` 已完成，直接参与下游 IllusDesign 生产。
> 无 `notes` 自由文本字段——鞋履归 footwear、配饰归 accessory_type、穿法与质感并入 garment、调性归 vibe、人物姿态气质不写（第二事实源必与结构化字段漂移）。
