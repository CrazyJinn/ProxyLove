# 属性撰写规范

> **定位**：Schema（各模块 .md）是**结构权威**（有什么节点/属性/边），本文是**内容权威**（怎么写）——全部自由文本与标签类属性的撰写规则，skill 生产与 dashboard 人工编辑共同遵循。只立规则，不设示例。Schema 字段表内以「撰写见《属性撰写规范》§N」指回本文。
>
> **治理对象**：LLM 生成字段的三类病——发散（越写越长、散文化）、越界（写到别的载体领地）、漂移（同一字段前后风格不一）。

---

## §0 总则（一切属性先过这四条）

1. **单一载体（全局不变式，分两侧执行）**：同一事实不允许出现在两个属性里。但写入 skill 在生成时刻只有局部视野（目标字段 + 本 skill 查到的数据），**无法也不需要**枚举全图载体。本不变式由两侧联合保证——
   - **写入侧（防新增，本规范的主体形式）**：规则一律写成**字段级禁则**——「写 X 时禁 Y 类内容」，做性质判定（这是不是情绪/神态/情境/事实？），不要求跨节点查重。§1-§5 各表的「不写」列即此形态。
   - **审计侧（查存量，另有载体）**：跨节点的同义双写靠全图扫描与 dashboard 体检发现，不指望写入方自查。载体对照表（场景美术.md「信息分层」/ 角色美术.md「人物建模三层」）供审计侧与人工编辑使用。
2. **只存当下有效值**：禁日期注记、推导过程、编号引用、归属标注、变更历史。历史不入图。
3. **正向陈述**：只写「是什么」，不写「不是什么/不再/改为」——否定句在下游生成链会被反向理解。负面红线类内容按既定决策宁可丢不保留。
4. **默认不填**：字段存在需要理由；无增量时留空不是缺陷，是纪律。占位仅允许「内容待补」级最小占位。

## §1 vibe 调性族（最易发散，最高优先级）

**共同定义：vibe = 把某物（人/景/表情/乐）的恒定内核翻译成感官可感的调性——不是描述它，是给它定调。**

### 1.0 共同四问（每个 vibe 写完必过）

1. **会变吗**——放在叙事开头和结尾都成立；任何随剧情失效的表述归 Event/SubEvent。
2. **有感官落点吗**——颜色/质感/光线/声音/温度至少落一个；性格或氛围的直白形容不是 vibe，须翻译成通感。
3. **越界了吗**——不写任何归其他载体的事实（见特化表边界列）。
4. **够短吗**——按特化表长度；写不进限定篇幅说明在复述不是在定调。

### 1.1 成员特化

| 成员 | 翻译对象 | 服务对象 | 边界（不写） | 长度 |
|---|---|---|---|---|
| **Character.vibe** | 性格内核 → 感官调性（含配色方向） | 造型 / 声线 / 写手 | 生理外貌（归 AppearanceStyle）、身份事实（归 Lore）、剧情因果（归 Event）、台词样例 | 一段（2~3 句） |
| **Scene.vibe** | 该机位画面的恒定味道 | 场景出图 / 读图取材 | 陈设小物（归 deco）、空间定位（归 Spot.description）、剧情语境（归 anchored_at）、人物持物、构图光影数值（归 room.yml） | 一句（可含天气） |
| **StandingIllustration.vibe** | 该表情变体的情绪调性 | 立绘出图（表情强度/朝向/张力） | 台词情境与剧情语境、着装（归 CostumeStyle）、参考图已有的持物 | 1~2 句 |
| **BgmTrack.vibe** | 该曲音乐本身的味道 | 外部生成工具 / 展示 | 场景画面（归源 Scene.vibe）、剧情、织体/BPM/结构细节（归 prompt） | 1~2 句 |

### 1.2 调性词不互斥原则

同域多个 vibe 允许共享底色（同角色各变体同气场、同 Location 各 Scene 同基调），但每条必须有自己的区分句——两条 vibe 只差形容词顺序 = 其中一条该删。

## §2 事实族（叙事域自由文本）

| 属性 | 写什么 | 不写什么 / 检验法 |
|---|---|---|
| **Event.title** | 一句话可独立成立的事实句（主谓宾） | 检验：能否直接当「已发生的事」陈述出来 |
| **Event.description** | title 装不下的钉子细节 1~3 句（数字/物件/氛围摘句） | 不复述 title、不写后果（后果是另一 Event + leads_to）、不写认知解读（归 Hook） |
| **SubEvent.description** | 该演出段的节拍级内容：2~4 分句、每分句一个节拍 + 互动方向 | 不写字段头/台词原文/道具环境细节/氛围；时间地点人须与父 Event 相容 |
| **Hook/Lore.title** | 干净的事实陈述 = 事实本体 | 禁备忘/推导/归属标注；检验：拿掉本节点，这条信息在图上无处可寻——是则 title 合格承载 |
| **Hook/Lore.content** | **默认不填**。仅当「图上其他实体无载体」的增量（如定义式） | 不做 title 的扩写、不举剧情例子 |
| **Choice.description** | 选择发生那一刻的情境一两句 | 不写各选项后果（由 option 边承载） |
| **Section.summary** | 本节戏剧职责一句话 | 不写剧情梗概、不写主旨（那是 StoryArc） |
| **StoryArc.description** | 两段式：主旨一两句 + 氛围一段（「主旨：」「氛围：」引导） | 不复述情节结构/时序/时刻（唯一承载 = 成员 Event.time）；详细规范见 剧情.md |
| **Location.description** | 一句话空间定位（地理/功能） | 视觉不写（归 Scene.vibe/deco）、剧情不写 |
| **Spot.description** | 一句空间描述（这是什么区域） | 同上 |

## §3 指令族（喂给外部生成器的文本）

| 属性 | 写什么 | 不写什么 |
|---|---|---|
| **VoiceDesign.instruct** | 六要素各一个明确值：年龄/性别/音色/气质/语速/尾音 | 不写台词样例、不写模糊愿望；改音色 = 改原文而非追加 |
| **BgmTrack.prompt** | 完整配方：场景曲定位 + 情绪基调 + 织体 + BPM + 结构（循环友好/总长）+ 收尾禁令 | vibe 是味道、prompt 是配方——配方展开味道，不复述画面 |
| **DesignSheet.delta_notes** | 增量版本专用：相对参考版的口述变更 | 首版留空；不写未变更维度；不改写旧版 |
| **LineAudio.tts_text** | text 的标点/停顿级变体 | **禁增删改任何汉字**；不得写回 text；一句一变体 |
| **LineAudio.prompt**（bed_start） | AudioFly 英文提示词 | 重产复用原文，不即兴改写 |

## §4 标签族（结构化短文本）

- **标签就是标签**：短语，不是句子；出现完整句 = 描写化，归 vibe 层重写。
- **合成组合顺序固定**（顺序即解析约定，下游按序读）：hair = 发色+发型+发长；eye = 瞳色+眼型；garment = 材质+服装类型（多件分号）。
- **多值分隔符统一半角 `;`**，不混用顿号逗号。
- **variant_label** 2~4 字，情绪词/动作词；同 IllusDesign 下不重复。
- **enum 字段严格取枚举值**，不自造同义词——条件表达式与查询按字面匹配。

## §5 边语境族（边上的 detail/label）

| 属性 | 写什么 | 检验法 |
|---|---|---|
| **occurs_at.detail** | 该地点在本事件中的角色，两三词 | 不复述事件 |
| **leads_to.detail** | 因果语境（为什么前者导致后者） | 删掉后因果仍可从两端 title 推出 = 可不填 |
| **anchored_at.detail** | 归组依据 | 能说明「为什么是这个机位」 |
| **appears_as.detail** | 着装语境 | 不描写服装本身（归 CostumeStyle） |
| **relation.detail** | 关系状态词 | 状态变化建新边 + 时间区间，不改写旧边 |
| **option.label** | 玩家看到的选项文本原样 | **不得重复**（condition 按字典序编号，重复 = 序号歧义）；改 label = 改全部引用序号 |

## §6 反模式速查（见到即打回）

1. 情境复述（谁在哪做了什么、台词原文、编号引用）出现在任何非事实族属性
2. 日期/编号引用/人名归属括注——备忘泄漏
3. 否定式描述——改正向
4. 两条同域 vibe 几乎相同——冗余，删一条
5. title 与 description 首句重复——description 砍掉复述
6. 标签字段出现完整句子——描写化
7. enum 字段出现枚举外同义词——漂移
8. content 在做 title 的扩写——删 content
