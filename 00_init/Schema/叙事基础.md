# 01 叙事基础

> 角色、地点、空间细分、信息——故事世界的 4 种基本实体；信息（Info）含事件（Event）/ 选择分叉（Choice）两种附加 label 形态（多 label 建模，2026-10-12 合并，见 [02_剧情数据/Info合并迁移-20261012/](../../02_剧情数据/Info合并迁移-20261012/README.md)）。

---

## 节点

### 角色（Character）

最小粒度：每个有名字的真实人物。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 姓名 | string | 是 | `陆择` |
| gender | 性别 | enum | 否 | `男` / `女` |
| description | 简介 | string | 否 | `星耀电竞战队队长，沉默寡言的天才选手` |
| birth_year | 出生年份 | int | 否 | `2003` |
| character_tags | 人设标签 | string | 否 | `沉默寡言, 外冷内热, 完美主义` |
| color_direction | 配色逻辑 | string | 否 | 自由文本：主辅点缀色与明暗逻辑（由 char-concept-designer 填充） |
| priority | 优先级 | enum | 否 | `P0` / `P1` / `P2`：制作优先级，P0 最优先（分组见 [00_init/大纲.md](../../00_init/大纲.md)） |

---

### 信息（Info）——叙事认知基础节点（含 Event / Choice 附加形态）

最小粒度：一条对读者有意义的新认知。**多 label 建模**：全部节点带基础 label `:Info`；事件与选择再挂附加 label——

- 事件节点 `:Info:Event`：某时某刻发生的某件事，一个有明确时间点的具体动作或状态变化；
- 选择节点 `:Info:Choice`：一个玩家选择分叉点（galgame「玩家选择」一等公民化，显式建模「在哪选择、不同选项导向不同后续」）；
- 纯信息节点仅 `:Info`：一个之前不知道的事实。

**查询约定**：

- `MATCH (n:Event)` / `MATCH (n:Choice)`：附加 label 可独立匹配，事件/选择查询写法不变；
- `MATCH (n:Info)`：三类超集；统计纯信息须显式 `WHERE NOT n:Event AND NOT n:Choice`；
- 显示名统一 `title`（2026-10-12 迁移：Choice 原 `name` 已转 `title` 并移除；`content`（纯信息正文）与 `description`（事件/选择描述）语义不同，不合并）；
- `labels()` 返回顺序**无保证**——取主显示 label 用优先级解析（Event > Choice > Info），禁止 `labels(n)[0]`（dashboard 侧统一入口 `app/services/labels.py`）；
- id 唯一性由全库约束保障（`<label>_id_unique`，2026-10-12 起，21 个 label 各一条）。

**统一字段表**（按适用范围分组；同一节点可兼具多组字段——如一个 `:Info:Event` 也可带 content）：

| 字段 | 中文 | 类型 | 必填 | 适用范围 | 示例 |
|------|------|------|------|---------|------|
| id | 编号 | string | 是 | 全部 | snowflake Base62 |
| title | 标题 | string | 是 | 全部 | `陆择加入星耀电竞` / `陆择是孤儿` / `跳江选择` |
| content | 内容 | string | 是 | 仅纯 Info | `陆择从小在孤儿院长大，从未见过亲生父母` |
| knowledge_level | 知识层 | enum | 是 | 仅纯 Info | `2` |
| time | 时间 | Date | Event 必填 / Choice 可选 | Event / Choice | `2024-04-11` / `Day 0 深夜` |
| description | 描述/情境 | string | 否 | Event / Choice | 事件描述 / 选择发生的情境描述 |
| type | 类型 | enum | 否 | 仅 Event | `行动` |
| ending_kind | 结局类型 | enum | 否 | 仅 Event | `BE` / `TE` / `HE` / `NE`（非结局留空） |

**knowledge_level 枚举**（纯 Info）：
- `1`：表层——新闻报道、警方通报等公开信息
- `2`：参与层——需要阅读聊天记录、转账记录等细节才能了解的信息
- `3`：深层——需要综合推断或获取非公开信息才能理解的隐性事实

**type 枚举**（Event 形态）：
- `行动`：具体的物理行为，如跳江、转账、报警
- `交流`：对话、发帖、聊天记录等沟通行为
- `转折`：改变事态走向的关键节点
- `状态变化`：人物状态或关系状态的改变，如分手、确诊

**ending_kind 枚举**（Event 形态，结局事件标记，可选）：`BE` Bad Ending / `TE` True Ending / `HE` Happy Ending / `NE` Normal Ending。非结局事件不填。结局不单独建节点，`option{leads_to_ending:true}`（见下）指向的 `:Info:Event` 即结局事件。

大纲设定：灵魂穿越者只能在关键选择节点干预，而关键选择节点 = 玩家的选择项。

> Info 家族（含 Event/Choice 形态）无 status 字段、不参与生产流水线与审批级联，与 Character/Location/Spot 同属纯叙事实体。
> 叙事范围现状：图内叙事数据截至 ch01（开场 ~ Day 10）；Day 11+ 剧情节点已于 2026-10-12 剪枝移除（快照可恢复，见迁移 README）。

### 地点（Location）

最小粒度：具体地点/游戏场景。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `重庆长江大桥` |
| description | 描述 | string | 否 | `横跨长江的公路铁路两用桥` |

> Location 创建时必须同步创建默认 Spot（`kind='default'`，name=`<Location名>-未细分`），由 NRT/graph-builder 在建地点的语句里一并 MERGE。查询「事件发生在某地点」一律经 Spot 两跳：`(e)-[:occurs_at]->(sp:Spot)-[:part_of]->(l:Location)`。Location 改名时须连带改其全部 Spot 名（前缀同步，治理纪律——realizes sync=false，图上无级联提示）。

---

### 空间细分（Spot）

最小粒度：地点内的子空间。事件定位的锚点——所有 `occurs_at` 挂 Spot，禁止直挂 Location。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | **一律 `<Location名>-<区域>`**：zone 如「八楼出租屋-电脑桌区」；default 约定 `<Location名>-未细分`。区域段（短名）不得含文件系统保留字符（`\ / : * ? " < > |`）——它是产物目录名（`07_场景美术/<Location名>/<短名>/`） |
| kind | 类型 | enum | 是 | `default`（未细分）/ `zone`（细分区域） |
| description | 描述 | string | 否 | 一句空间描述（如「地铁车厢内部」） |
| dsl_path | DSL 路径 | string | 否 | `07_场景美术/<Location名>/<Spot目录名>/<Spot短名>.room.yml`（该 spot 的 3D 布局真源相对路径，由 scene-designer 登记）。**Spot 目录名**：zone 取短名，default 取 Location 名，撞名复用 default 目录。**挂靠单元 = Spot（建模单元，通常即物理房间）**：同一物理空间的叙事细分优先吸收为同 Spot 多 Scene（机位/时间窗版本），确需拆 zone Spot（≈新物理空间）时才产新文件。**非空 = 该 spot 已 3D 建模**——其 realizes 的全部 Scene 出图由 scene-layer-designer 调 `slice_scenes.py --emit-prompt` 现场投影直写 prompt.md（文件内以 `scenes[].scene_id` = Scene.id 定位机位条目；无派生中间文件）；为空走旧自由文本组装（回退面）。详见 [场景美术.md](场景美术.md) |

> Spot 无 status、不参与生产流水线，与 Character/Location/Info（含 Event/Choice 形态）同属纯叙事实体。每个 Location 恰好 1 个 default Spot；zone Spot 由叙事文本的子空间证据触发创建（禁止硬猜）。
> zone Spot 与同名 Scene 不冲突（label 不同且 realizes 边显式连接）；default Spot 名约定「-未细分」避免与任何 zone 撞名。

## 边

> 所有边方向：**上游 → 下游**。`sync` 属性控制级联同步。

### relation — 人物关系 `N:N`

- **方向**：`Character → Character`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关系类型 | string | 是 | 如"恋爱""亲属""同事""仇人" |
| detail | 详情 | string | 否 | 如"恋爱中""已分手""姐弟" |
| start_time | 开始时间 | Date | 否 | 关系建立的时间 |
| end_time | 结束时间 | Date | 否 | 关系结束的时间（为空表示持续中） |
| sync | 同步 | boolean | 否 | 默认 `false` |

> 关系可随时间变化：如恋人分手后变为仇人，应建两条 relation 边，分别标记不同的时间区间。

---

### involved — 人物参与事件 `N:N`

- **方向**：`Character → :Info:Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| role | 角色 | string | 是 | 如"当事人""目击者""受害者""施害者""参与者" |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### occurs_at — 事件发生子空间 `N:1`

- **方向**：`:Info:Event → Spot`
- **不变式**：每个 Event 恰好 1 条 occurs_at；禁止 Event→Location 定位边（Event 不得有任何直指 Location 的边）。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| anchor | 锚点级别 | enum | 是 | `spot`=细分 Spot（精确）；`default`=默认 Spot（当前未细化，细化时机由 scene-designer 重跑时按叙事密度判断）。anchor 与目标 Spot.kind 须一致 |
| detail | 详情 | string | 否 | 如"跳江地点""约会地点" |
| sync | 同步 | boolean | 否 | 恒 false（纯叙事域边，无生产下游） |

### part_of — 空间从属 `N:1`

- **方向**：`Spot → Location`
- **不变式**：每个 Spot 恰好 1 条 part_of；每个 Location 恰好 1 个 default Spot 子节点。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 恒 false（叙事域内部边） |

---

### at — 人物—地点 `N:N`

- **方向**：`Character → Location`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | string | 是 | 如"居住""前往""工作" |
| detail | 详情 | string | 否 | |
| start_time | 开始时间 | Date | 否 | 关联开始的时间 |
| end_time | 结束时间 | Date | 否 | 关联结束的时间（为空表示持续中） |
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### link — 信息关联 `N:N`

- **方向**：`Character / :Info:Event / Location → :Info`
- **限制**：仅叙事三大基础实体（Character、Event 形态、Location）可关联 Info。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | string | 是 | 如"涉及""因果" |
| detail | 详情 | string | 否 | |
| time | 时间 | Date | 否 | 信息关联发生的时间 |
| sync | 同步 | boolean | 否 | 默认 `false` |

**特殊规则**：`type=因果` 时仅用于 `Info → Info`，表示原因→结果。

---

### evt_relation — 事件关联 `N:N`

- **方向**：`:Info:Event → :Info:Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | enum | 是 | `因果` / `先后` / `包含` |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

**type 方向语义**：`因果` = 前因→后果；`先后` = 时间顺序；`包含` = 大事件→子事件

---

### presents — 事件触发选择 `N:N`

- **方向**：`:Info:Event → :Info:Choice`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false` |

> 某事件播放到此呈现选择。事件是源头（上游），选择由事件触发（下游），符合全局上游→下游。

### option — 选项导向后续 `N:N`

- **方向**：`:Info:Choice → :Info:Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| label | 选项文本 | string | 是 | 玩家看到的选项：`再想想` / `跳江` / `选苏晓禾` |
| leads_to_ending | 导向结局 | boolean | 否 | 默认 `false`；`true` 表示该选项进入结局 |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

> 选择是因（上游），选完进入的事件是果（下游）。事件流嵌入：`:Info:Event -presents-> :Info:Choice -option-> :Info:Event`，Choice 作为分叉点嵌在事件链中间。

**Choice 与 evt_relation 的分工**：
- `evt_relation`（Event→Event，即 `:Info:Event` 之间）：事件链内部的因果 / 先后 / 时序串联。
- `Choice + presents + option`：管「在哪选择、选项导向哪条分支」，是分叉发源点。
- 分支点原先靠 `evt_relation{type:包含}` + title 文案后缀（「（分支A）」「BE」）hack，现由 `option` 边承载分支语义；主线 `先后 / 因果` 不受影响。

## ID 规则

所有节点使用雪花算法 Base62 编码作为 `id` 属性值（如 `Nv93TkkkgC`），全局唯一，无前缀。由 `.claude/scripts/snowflake_base62.py` 生成。

生成命令：
```bash
python "${CLAUDE_SKILL_DIR}/../../scripts/snowflake_base62.py" -n 1 -q
```

引用已有节点时，通过名称从数据库查询：
```cypher
MATCH (c:Character) WHERE c.name='角色名' RETURN c.id AS id
MATCH (e:Event) WHERE e.title='事件标题' RETURN e.id AS id
MATCH (s:Location) WHERE s.name='场景名' RETURN s.id AS id
MATCH (sp:Spot) WHERE sp.name='空间名' RETURN sp.id AS id
MATCH (i:Info) WHERE i.title='信息标题' RETURN i.id AS id
MATCH (ch:Choice) WHERE ch.title='选择名' RETURN ch.id AS id
```
