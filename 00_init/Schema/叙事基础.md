# 01 叙事基础

> 角色、事件、地点、信息、选择分叉、故事线——故事世界的 6 种基本实体。空间细分（Spot）已移至场景域（见 [场景美术.md](场景美术.md)）。

---

## 节点

### 角色（Character）

最小粒度：每个有名字的真实人物。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 姓名 | string | 是 | `陆择` |
| gender | 性别 | enum | 否 | `男` / `女` |
| birth_year | 出生年份 | int | 否 | `2003` |
| ref_image_path | 参考图路径 | string | 否 | `06_角色美术/<char_id>/参考图.jpg`（hexid 段；dashboard 上传时 SET，char-design-sheet 探测读属性） |
| priority | 优先级 | enum | 否 | `P0` / `P1` / `P2`：制作优先级，P0 最优先（分组即本字段值，以图上 Character 现状为准） |
| vibe | 设计氛围 | string | 否 | 人物调性的单一事实源（自由文本，一段有画面感的氛围描述；生成规范见下方「vibe 生成规范」） |
| status | 占位标记 | int | 否 | 仅占位语义：`0`=占位待建档（event-ideator/stager 经建议 JSON 建，char-design 圈占位消化）；消化建档后 **REMOVE 归空**。非生产流水线状态 |

**vibe 生成规范**（核心思想：把人物的性格内核，翻译成感官可感的调性——不是在描述这个角色，而是在给这个角色「定调」）：

1. **源头是性格，落点是感官**——输入是「他骨子里是什么样的人」，输出必须是通感表达：这段性格看起来是什么颜色、摸起来是什么质感、走进房间时空气怎么变。性格直述（「外冷内热」）不是 vibe，翻译完成（「冷调象牙白与深酒红的克制，暗金点睛」）才是。
2. **一段文本服务三个创作端**——造型师选面料配色、声线师定音色气质、写手定出场氛围，读同一段话取到的味道必须一致。写前自问：这三个人拿到这段话，各自知道往哪个方向使劲吗？
3. **只写恒定调性，不写任何会变的东西**——生理外貌（发色/瞳色/肤色/体型）归 AppearanceStyle 结构化字段；设定事实（职业/家世/经历/能力）归 Lore；剧情因果归 Event。检验法：**把这段话放在第一章和最后一章，它都还成立吗？** 成立才是 vibe；会过时的说明写进事实了。

### 事件（Event）

最小粒度：某时某刻发生的某件事。一个事件 = 一个有明确时间点的具体动作或状态变化。

> **Event 记「发生」，Hook 记「埋设」，Lore 记「固有」**——需要在故事时间轴上被演出、直接推进剧情的事建 Event；因某事件成立的认知建 Hook；角色/地点固有属性建 Lore（判定测试见下文 [钩子（Hook）与设定（Lore）](#事实fact与设定lore) 节）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `陆择加入星耀电竞` |
| time | 时间 | string(datetime) | 是 | `yyyy-MM-dd HH:mm:ss`（如 `2024-06-14 19:00:00`），**自时间锚点推算**（锚点见 [游戏概览.md](../游戏概览.md) 基本信息）；字符串序即时间序，计算用 `datetime(e.time)` 现场转换 |
| description | 描述 | string | 否 | |
| type | 类型 | enum | 否 | `行动` |
| ending_kind | 结局类型 | enum | 否 | `BE` / `TE` / `HE` / `NE`（非结局留空） |
| condition | 条件判断 | string | 否 | 条件表达式（语法见下方「condition 条件表达式」）；空/缺省 = 无条件，主线默认可激活 |

**type 枚举**：
- `行动`：具体的物理行为，如跳江、转账、报警
- `交流`：对话、发帖、聊天记录等沟通行为
- `转折`：改变事态走向的关键节点
- `状态变化`：人物状态或关系状态的改变，如分手、确诊

**ending_kind 枚举**（结局事件标记，可选）：`BE` Bad Ending / `TE` True Ending / `HE` Happy Ending / `NE` Normal Ending。非结局事件不填。结局事件由 [剧情.md](剧情.md) 的 `Choice -[option {leads_to_ending:true}]-> Event` 指向。

**condition 条件表达式**（选填；空 = 无条件，主线默认可激活）：

值为一个字符串，表达「玩家选择史」上的布尔条件——本 Event 仅当条件求值为真才可激活。典型用途：分支汇合点的软门控（玩家做过某选择后，另一条线上的后续事件才解锁）。

- **原子**（唯一原子类型）：`choice:<choice_id>[<n>]` —— 语义：「玩家在 Choice `<choice_id>` 选择了第 `n` 个选项」为真。
- **组合**：优先级 `!` > `&` > `|`，圆括号分组。例：`choice:RGj3o4sKsD[2] & !choice:RGcLQj1YBt[1]` = 「在 RGj3o4sKsD 选了第 2 项，且在 RGcLQj1YBt 没选第 1 项」。
- **选项序号 n 的定义**：该 Choice 全部出边 `option` 按 `label` 字典序（Unicode 升序）排列的 **1 基序号**。书写/校验时的可复现查询：
  ```cypher
  MATCH (c:Choice {id:'<choice_id>'})-[o:option]->(:Event)
  RETURN o.label ORDER BY o.label
  ```
- 注意：
  - **字典序 ≠ 叙事呈现顺序**。例：「三选一」三个选项 label 为 选林梦/选苏晓禾/选沈暮雪，字典序 林 < 沈 < 苏，故 `[1]`=选林梦、`[2]`=选沈暮雪、`[3]`=选苏晓禾。**写 condition 必须现查上表，不靠记忆**。
  - 同一 Choice 的 option.label **不得重复**（否则序号歧义）；改 label 等于改全部序号——凡被 condition 引用的 Choice，调整选项 label 前必须排查引用。
  - 求值输入 = 玩家选择史（运行时状态）；图上 option 边全集只提供序号基准，不承载「玩家实际选了什么」。
- **校验**（人工/工具自检，非法不落库）：choice_id 在图中存在；`n` ≤ 该 Choice 的 option 总数；括号配对；无空原子。

**语法（BNF）**：

```
condition := ε | expr
expr      := term ( "|" term )*
term      := factor ( "&" factor )*
factor    := "!" factor | atom
atom      := "choice:" choice_id "[" n "]"
choice_id := [0-9A-Za-z]+        （雪花 Base62）
n         := [1-9][0-9]*         （1 基正整数）
```

### 细化事件（SubEvent）

最小粒度：父事件（Event）在机位层的演出物化——到场/离开/换区/换装等演出段。一个 Event 可细化出多个 sub，一个 sub 只属一个父（存量分布 0~4 sub/事件；无 sub 事件=显式工作缺口，交 event-stager 补细化）。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `<父事件title> · <机位名>` |
| time | 时间 | string(datetime) | 是 | 继承父事件或时间插值 |
| description | 描述 | string | 否 | 演出内容（台词/动作） |

- SubEvent **无** status / type / ending_kind / condition / involved / occurs_at——叙事身份（时间、人物、地点、因果、分支）全部在父 Event 层；sub 只承载 `anchored_at→Scene` 与 `appears_as→IllusDesign` 两边。
- **时间轴查询只碰 Event**（label 隔离——SubEvent 不干扰 Event 时间轴/时间窗查询）。
- 删父 Event 必须连带删其全部 sub。

### 地点（Location）

最小粒度：具体地点/游戏场景。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `重庆长江大桥` |
| description | 描述 | string | 否 | `横跨长江的公路铁路两用桥`（一句话空间定位：地理/功能说明；场景视觉记录在美术域 Scene.description） |
| status | 占位标记 | int | 否 | 仅占位语义：`0`=占位待建档（event-ideator/stager 经建议 JSON 建，scene-design 圈占位消化）；消化建档后 **REMOVE 归空**。非生产流水线状态 |

> Event 定位一律 `occurs_at → Location`（一跳）；机位归组 `anchored_at → Scene` 只存在于 SubEvent 层（定义见 [场景美术.md](场景美术.md)）。Spot 经 `part_of` 从属 Location（方向 Location→Spot）。Location/Spot 改名**零漂移**——产物目录锚 id（见 [场景美术.md](场景美术.md) 头部 id 锚定注记），旧「连带改全部 Spot 名前缀」纪律已废（realizes sync=false 依旧：改名不作废机位图）。

### 钩子（Hook）与设定（Lore）

最小粒度：一条**成立的事实**（Hook）或一条**固有设定**（Lore）。与 Event 对仗：**Event 记「发生」，Hook 记「埋设」，Lore 记「固有」**（原 Info label 2026-11-11 拆分退役）。

- **Event = 行为、事件**——需要在故事时间轴上**被演出**、直接推进剧情的事：有参与者、发生即改变局面，可细化演出（`refines → SubEvent` 落机位）。
- **Hook = 事件性事实**——因某事件而成立的世界状态（如「视频火了」「沈暮雪辞职」）。有揭示主场：`reveals` 锚定读者侧知晓时刻，一次性显性交付为主。
- **Lore = 固有设定**——角色/地点的固有事实（人设底色、世界观规则、背景前史）。无揭示主场、无时间轴位置，反复以侧面折射方式被消费；**暴露节奏由写作层遗忘曲线算法管制**（chapter-novelist freshness，见其 skill），图上不计划。
- **判定测试**：这个内容要不要在时间轴上「演出来」？要 → Event；因某事件成立的认知 → Hook；角色/地点固有属性 → Lore。一件事的数字细节、氛围摘句归 `Event.description`，**不另立**（防复述）；角色间双边关系事实优先 `relation` 边承载。
- **挂靠（Hook/Lore 无出边，只被指向）**：
  - **Hook 成立轴**：`Event ─establishes→ Hook`（何事成立它，如 递交辞呈→「沈暮雪辞职」）。**由 event-ideator 产**。
  - **Lore 宿主**：`(Character|Location) ─has_info→ Lore`（谁/何地的固有设定，如 陆择→「陆择是海王」）。构图期人工拍板。
  - **Hook 揭示轴**：`SubEvent ─reveals→ Hook`（读者在哪场戏知晓，如 训练馆冲突→读者知道了「江烈零容忍个人主义」）。**由 event-stager 产**（拆 sub 时逐 sub 拍揭示场合——演出域决策）；**目标为 Lore 或源为 Event 均违规**（Lore 无揭示时刻；Event 级 reveals 已废止下沉，体检项兜查）。
  - title/content 为干净的事实陈述，**禁备忘/推导文字**（日期注记、编号引用推导、归属标注）；变更历史不落图。

#### 钩子（Hook）

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `沈暮雪辞职` |
| content | 内容 | string | 否 | title 之外的增量补充（图上其他实体无载体），非必要不填；示例 `弱者＝认真对待感情却伤痕累累的人` |
| knowledge_level | 知识层 | enum | 是 | `1` |

#### 设定（Lore）

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `陆择生前情史泛滥` |
| content | 内容 | string | 否 | 同 Hook——title 即事实，非必要不填；示例 `父亲罚站屋外` |
| knowledge_level | 知识层 | enum | 是 | `3`（亦为 freshness 半衰期档位：1→h12 / 2→h6 / 3→h3） |

**knowledge_level 枚举**：
- `1`：表层——新闻报道、警方通报等公开信息
- `2`：参与层——需要阅读聊天记录、转账记录等细节才能了解的信息
- `3`：深层——需要综合推断或获取非公开信息才能理解的隐性事实

### 选择分叉（Choice）

最小粒度：一个玩家选择分叉点。把 galgame「玩家选择」一等公民化——显式建模「在哪选择、不同选项导向不同后续」。

世界观设定（见 [00_init/游戏概览.md](../../00_init/游戏概览.md)）：灵魂穿越者只能在关键选择节点干预，而关键选择节点 = 玩家的选择项。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `跳江选择` / `三选一` |
| description | 情境 | string | 否 | 选择发生的情境描述 |
| time | 时间 | string(datetime) | 否 | `yyyy-MM-dd HH:mm:ss`，自时间锚点推算（选填） |

> Choice 无 status 字段、不参与生产流水线，与 Character/Event/Location/Hook/Lore 同属纯数据实体。

**结局**：结局不单独建节点，仍用 `Event` + 可选属性 `ending_kind`（`BE`/`TE`/`HE`/`NE`）表达；`option{leads_to_ending:true}`（见下）指向的 Event 即结局事件。

### 故事线（StoryArc）

最小粒度：一条贯穿多个事件的叙事弧线（如「陆择的救赎线」）——对「哪些事件同属一条弧」的规划注记，本身不在时间轴上占位。

> **StoryArc 记「规划」，Event 记「发生」**——故事线不是新事件类型，是对事件集合的叙事意图注记；由 event-ideator 起草与对账维护，成员由 `comprises` 边物化。**并非所有 Event 都需挂故事线**——事件不进线≠不重要；comprises 只圈承载该线叙事意图的骨架事件，时间轴上的其余事件照常存在、照常被节 includes 出版。

| 字段 | 中文 | 类型 | 必填 | 示例 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| title | 标题 | string | 是 | `陆择的救赎线` |
| description | 主旨与氛围 | string | 是 | **写作思路层**自由短文，两段式：**主旨**（一两句：这条线想表达什么）+ **氛围**（一段：质感与调性），以「主旨：」「氛围：」引导、段间换行。不复述情节结构——时序由成员 `Event.time` 承载 |

- **无 status**：与 Chapter/Event 同惯例——叙事基础域节点不参与生产流水线，无审批态。
- **时间范围不落图**：故事线跨度由成员 `Event.time`（字符串序即时间序）承载，不存起止字段——与 Chapter「章的叙事范围由事件时间线承载」同款约定。
- **description 是主旨与氛围，不是事件复述**：写这条线想表达什么（主旨）与质感调性（氛围）——给下游（novelist 取材、ideator 补环）方向性约束；具体情节由成员 Event 承载，段内不复述事件细节。
- **description 不写时间戳与结构**：只写主旨与氛围，不写「先铺垫后逆转」式次序，具体时刻唯一承载是 `Event.time`。
- **与 Section includes 的分工**：`Section ─includes→ Event` 是**出版编排**（某节演哪些事件，order 承载节内次序）；`StoryArc ─comprises→ Event` 是**叙事规划**（哪些事件同属一条弧线，无 order）。同一 Event 既可被多节 includes、也可被多条故事线 comprises，两边互不感知。

## 边

> 所有边方向：**上游 → 下游**。`sync` 属性控制级联同步。

### relation — 人物关系 `N:N`

- **方向**：`Character → Character`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关系类型 | string | 是 | 如"恋爱""亲属""同事""仇人""控制"（控制者→受控者：受控者行为已不由其自身决定的一切形态） |
| detail | 详情 | string | 否 | 如"恋爱中""已分手""姐弟" |
| start_time | 开始时间 | string(datetime) | 否 | `yyyy-MM-dd HH:mm:ss`，自时间锚点推算 |
| end_time | 结束时间 | string(datetime) | 否 | 同上（为空表示持续中） |
| sync | 同步 | boolean | 否 | 默认 `false` |

> 关系可随时间变化：如恋人分手后变为仇人，应建两条 relation 边，分别标记不同的时间区间。

---

### involved — 人物参与事件 `N:N`

- **方向**：`Character → Event`

> 参与人的具体身份（来电者/发信人/在场者等）由事件本体（title/description）承载，边上不记。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### occurs_at — 事件发生地点 `N:N`

- **方向**：`Event → Location`
- **不变式**：每个 Event ≥1 条 occurs_at（跨地点事件挂多条，如 晨跑遇雨=南滨路+超市）；occurs_at 永远指向 Location。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| detail | 详情 | string | 否 | 如"跳江地点""约会地点" |
| sync | 同步 | boolean | 否 | 恒 false（纯叙事域边，无生产下游） |

> 事件到机位（Scene）的归组由 `anchored_at` 边承载（只挂 SubEvent 层，定义见 [场景美术.md](场景美术.md)）；本边无 `anchor` 属性。

---

### at — 人物—地点 `N:N`

- **方向**：`Character → Location`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| type | 关联类型 | string | 是 | 如"居住""前往""工作" |
| detail | 详情 | string | 否 | |
| start_time | 开始时间 | string(datetime) | 否 | `yyyy-MM-dd HH:mm:ss`，自时间锚点推算 |
| end_time | 结束时间 | string(datetime) | 否 | 同上（为空表示持续中） |
| sync | 同步 | boolean | 否 | 默认 `false` |

---

### establishes — 事实成立 `N:N`

- **方向**：`Event → Hook`
- **语义**：**成立轴**——Hook 因源事件而成立（事情发生 → 事实成立，如 递交辞呈 →「沈暮雪辞职」）。**由 event-ideator 产**（建议 JSON 含 Hook 节点 + 本边）。原 `link` 边已废止（曾归一至本边，2026-11-11 起 Character/Location 固有事实改走 `has_info → Lore`，本边端点收窄为 Event→Hook）。
- **限制**：每条 Hook ≥1 条 establishes 入边（事实必须有成立源）。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 恒 false（纯叙事域边） |

---

### has_info — 固有设定宿主 `N:N`

- **方向**：`(Character | Location) → Lore`
- **语义**：**宿主轴**——Lore 是宿主角色/地点的固有事实（如 陆择 →「陆择是海王」）。构图期人工拍板（ideator 辅助，建议 JSON）。
- **限制**：每条 Lore ≥1 条 has_info 入边（设定必须有宿主）。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 恒 false（纯叙事域边） |

---

### reveals — 读者侧揭示 `N:N`

- **方向**：`SubEvent → Hook`
- **语义**：**揭示轴**——锚定**读者/玩家侧**的信息释放时刻：通过该场戏（sub），读者知晓该 Hook（如 训练馆冲突 → 读者知道了「江烈零容忍个人主义」）。与写作层（novelist 信息释放节奏）一一对应；**由 event-stager 产**（拆 sub 时逐 sub 拍板——揭示发生在哪个机位是演出域决策）；一条 Hook 可被多个 sub 揭示（多段式释放），但每次揭示都应有叙事增量。
- **限制**：reveals 目标 Hook 应另有 establishes 成立源（揭示的前提是已成立）；**目标为 Lore 违规**（Lore 无揭示时刻，暴露节奏归遗忘曲线）；**源为 Event 违规**（Event 级已废止，2026-11-11 下沉至 sub）。**级联**：sub 被 sync 级联重细化时 reveals 边随父删除，重拆时 stager 重新拍。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 恒 false（纯叙事域边） |

---

### leads_to — 导致 `N:N`

- **方向**：`Event → Event`（单向——因果只存在于事件之间）
- **语义**：上游是下游的直接原因（因果），全局方向约定上游→下游。叙事层唯一的因果载体。事件与信息之间**不走因果边**：事实成立归 `establishes`、读者知晓归 `reveals`。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| detail | 详情 | string | 否 | 因果语境（如"剪辑发布后流量爆发"） |
| sync | 同步 | boolean | 否 | 恒 false（纯叙事域边） |

> 例：`Event(帅气翻盘) -leads_to-> Event(剪辑成视频)`；「视频火了」作为事实由 `Event(剪辑发布) ─establishes→ Hook(视频火了)` 成立，`SubEvent(林梦来电 · 厨房餐区) ─reveals→ Hook(视频火了)` 向读者揭示。

> 先后时序由 `Event.time` 字符串序承载（字符串序即时间序），不建时序边；Event 间关系只有 `leads_to` 因果边。

---

### refines — 细化 `1:N`

- **方向**：`Event → SubEvent`（父→子，与 `Location ─part_of→ Spot` 同向）
- **语义**：sub 是父事件在机位层的演出物化。一个 Event 可细化出多个 sub（到场/换区/离开），一个 sub 只属一个父。
- **级联**：sync=true——父事件属性变更（time/title/description）沿边作废其全部 sub，须重新细化。删父 Event 连带删全部 sub。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 是 | 恒 true（父属性变更→sub 重细化） |

> **Event 直挂 `anchored_at`/`appears_as` 为违规**：这两边只存在于 SubEvent 层（见 [场景美术.md](场景美术.md) / [角色美术.md](角色美术.md)）；发现 Event 直挂即结构错误（体检兜查）。

---

### presents — 事件触发选择 `N:N`

- **方向**：`Event → Choice`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `false` |

> 某事件播放到此呈现选择。事件是源头（上游），选择由事件触发（下游），符合全局上游→下游。

### option — 选项导向后续 `N:N`

- **方向**：`Choice → Event`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| label | 选项文本 | string | 是 | 玩家看到的选项：`再想想` / `跳江` / `选苏晓禾` |
| leads_to_ending | 导向结局 | boolean | 否 | 默认 `false`；`true` 表示该选项进入结局 |
| detail | 详情 | string | 否 | |
| sync | 同步 | boolean | 否 | 默认 `false` |

> 选择是因（上游），选完进入的事件是果（下游）。事件流嵌入：`Event -presents-> Choice -option-> Event`，Choice 作为分叉点嵌在事件链中间。

**Choice 条件、分支与因果的分工**：
- `Event.condition`：本事件的**激活条件**——玩家选择史上的布尔表达式（语法见事件节「condition 条件表达式」），管「什么时候才可能发生」；空 = 主线默认可激活。
- `Choice + presents + option`：管「在哪选择、选项导向哪条分支」，是分叉发源点；option 目标事件 = 选择后立即进入（硬跳转，不需要 condition）。
- `leads_to`：跨 Event 的因果链（直接原因）；先后时序不建边，由 `Event.time` 字符串序承载。
- condition 与 option 的关系：option 是「选完立刻去」（硬跳转）；condition 修饰**其他**依赖该选择结果的后续事件（软门控）——不紧跟选择发生，但玩家没做过该选择则本事件不激活。

---

### comprises — 故事线包含事件 `N:M`

- **方向**：`StoryArc → Event`
- **语义**：Event 是该故事线的一个成员。同一 Event 可属多条故事线（多线共存），一条故事线可含任意多事件。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 恒 false（照抄 includes 先例：防级联 BFS 穿 Event 中继；故事线挂/摘成员不作废任何生产下游） |

> **不存 order**：成员的叙事次序由 `Event.time` 字符串序承载，边上不重复记序（description 只记主旨/氛围，不记序）。

## ID 规则

所有节点使用雪花算法 Base62 编码作为 `id` 属性值（如 `Nv93TkkkgC`），全局唯一，无前缀。由 `.claude/scripts/snowflake_base62.py` 生成。

生成命令：
```bash
python "${CLAUDE_SKILL_DIR}/../../scripts/snowflake_base62.py" -n 1 -q
```

引用已有节点时，通过名称从数据库查询：
```cypher
MATCH (c:Character) WHERE c.name='角色名' RETURN c.id AS id
MATCH (e:Event) WHERE e.title='事件标题' RETURN e.id AS id
MATCH (s:Location) WHERE s.name='场景名' RETURN s.id AS id
MATCH (f:Hook) WHERE f.title='事实标题' RETURN f.id AS id
MATCH (l:Lore) WHERE l.title='设定标题' RETURN l.id AS id
MATCH (ch:Choice) WHERE ch.name='选择名' RETURN ch.id AS id
MATCH (a:StoryArc) WHERE a.title='故事线标题' RETURN a.id AS id
```
