# 03 场景美术

> 场景的渲染与适配——把叙事地点拆解为可生成的场景与图层。

> **Event 驱动化（已实施）**：`anchored_at` 端点由 Spot 上移到 Scene（迁移规则 = 存量边沿 `Spot─realizes→Scene` 一跳重挂）；`part_of` 方向翻转为 `Location → Spot`（父→子，与全局上游→下游约定统一）。

## 节点

> Location / Event 节点定义见 [叙事基础.md](叙事基础.md)。Location 仅保留叙事属性；空间细分由 Spot 承载（定义见下文），视觉信息下沉到 Scene。Event 经 `occurs_at` 直挂 Location（叙事期一跳定位），细化出的 sub 经 `anchored_at` 直挂 Scene（机位）。空间链统一父→子：`Location ─part_of→ Spot ─realizes→ Scene`（每 Scene 恰好 1 个源 Spot）。

### 空间细分（Spot）

最小粒度：地点内的子空间。按空间证据创建（或复用既有）：Location 上挂载的事件呈现子空间证据时细分出 zone，并把事件细化出的 sub 以 `anchored_at` 直挂到该 Spot realize 的 Scene（机位）——归组与拍机位一步完成（既有 spot 够用则只归组不新建）；叙事期 Event 只挂 `occurs_at → Location`。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | **一律 `<Location名>-<区域>`**：如「八楼出租屋-电脑桌区」；整点建模区域段=Location 名（如「服装店-服装店」，目录名即 Location 名）。区域段（短名）不得含文件系统保留字符（`\ / : * ? " < > |`）——它是产物目录名（`07_场景美术/<Location名>/<短名>/`） |
| kind | 类型 | enum | 是 | `zone`（细分区域）——Spot 只有 zone 一种 kind；存量 default Spot（服装店/灵魂夹缝/林梦家-未细分）保留为历史形态，不迁移不再建 |
| description | 描述 | string | 否 | 一句空间描述（如「地铁车厢内部」） |
| dsl_path | DSL 路径 | string | 否 | `07_场景美术/<Location名>/<Spot目录名>/<Spot短名>.yml`（该 spot 的 3D 布局真源相对路径）。**Spot 目录名**：取短名；短名恰等于 Location 名（整点建模）时目录即 Location 名（存量 default Spot 的目录同为 Location 名，天然一致）。**挂靠单元 = Spot（建模单元，通常即物理房间）**：同一物理空间的叙事细分优先吸收为同 Spot 多 Scene（机位/时间窗版本），确需拆 zone Spot（≈新物理空间）时才产新文件。**非空 = 该 spot 已 3D 建模**——其 realizes 的全部 Scene 出图 prompt 由 room.yml 机位条目现场投影直写（文件内以 `scenes[].scene_id` = Scene.id 定位机位条目；无派生中间文件）；为空走自由文本组装（回退面） |

> Spot 无 status、不参与生产流水线。创建纪律：证据明确命中唯一既有 zone 时自动归组；歧义点（多 zone 命中/粒度歧义/证据不足）须人工敲定（禁止硬猜）。原「无子空间证据兜底 default Spot」机制已废止——整点需求由短名=Location 名的整点 zone 承载。
> zone Spot 与同名 Scene 不冲突（label 不同且 realizes 边显式连接）。

### 场景（Scene）

每个 Spot 一个或多个（时段/版本变体各一 Scene）。定义子空间在某时段/版本下的视觉设定。**Scene = 源 Spot 的 room.yml 内一个机位条目**（`scenes[].scene_id` = Scene.id，含 camera/lights；room.yml 路径登记在源 Spot 的 `dsl_path`，见上文 Spot 节点）。纯数据节点（按 Location 粒度推导、Spot 粒度产出），创建后即 `status=1`（已完成，无审批）。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `[Location名]-[区域]`，如 `咖啡店-点餐台`（可与 zone Spot 同名，label 与 realizes 边已区分）；时段/版本后缀（-更新设备后/-夜晚）只出现在 Scene 名 |
| scene_type | 场景类型 | enum | 是 | `dialogue`（对话背景）/ `functional`（功能场景）/ `combat`（战斗场景）/ `ui`（UI背景）。决定所需图层（见下表） |
| time_of_day | 时段 | string | 否 | 标签：清晨/白天/黄昏/夜晚。出图经 `--tod` 进模式 E prompt；Godot 运行时时段以此为准 |
| atmosphere | 氛围 | string | 否 | 自由文本：整体氛围一句话（含天气表达，如「雨幕笼罩的路口」） |
| deco | 陈设细节 | string | 否 | 自由文本：该机位画面里的陈设/小物描述——可移动小物与杂物堆**不建 room.yml 几何**，视觉表现全写此处（出图时经 `--deco` 传入 slice_scenes.py 拼 prompt；room.yml 的 scene 条目只留几何/数值，不存文字） |
| description | 概要 | string | 否 | 简短场景描述（1-2 句） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**：`0` 待设计 → `1` 已完成

> Spot 无 weather/composition/lighting/color_direction 字段：氛围=atmosphere，构图=room.yml 机位投影，光影=yaml `lights`，配色=美术风格.md 全局风格。

---

### 场景图层（SceneLayer）

场景的单一图层（传统 2D 游戏 4 层结构）。用 `layer_type` 区分背景/地面/陈设/遮罩；每个场景按 `scene_type` 按需拥有图层节点。

| 字段 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| id | 编号 | string | 是 | snowflake Base62 |
| name | 名称 | string | 是 | `[Scene名]-[图层中文]`，如 `咖啡店-点餐台-背景` |
| layer_type | 图层类型 | enum | 是 | `background`（背景）/ `floor`（地面）/ `decor`（陈设）/ `mask`（遮罩） |
| prompt_path | 提示词文件 | string | 否 | 派生 prompt 文件相对路径（`07_场景美术/<Location名>/<Spot目录名>/<Scene名>/<layer_type>/prompt.md`），由 assembler 从 Scene 字段 + 美术风格.md 生成 |
| image_path | 图片路径 | string | 否 | `07_场景美术/<Location名>/<Spot目录名>/<Scene名>/<layer_type>/<layer_type>.png`（与 prompt.md 同层——图层子目录内 prompt.md + <layer_type>.png 配对） |
| status | 流程状态 | int | 否 | `0` |

**status 枚举**：`0` 待生成 → `1` 提示词文件已生成 → `2` 图片生成完成 → `10` 待审 → `11` 批准

> **图层渲染顺序**（底→顶）：background 背景 → floor 地面 → decor 陈设 →（角色）→ mask 遮罩。遮罩层渲染在角色之上，形成前景遮挡。

## 边

### 场景数据关联

#### anchored_at — 事件机位归组 `N:N`

- **方向**：`SubEvent → Scene`（scene 域）
- **基数**：每个 SubEvent 0..N 条——sub 是父事件在机位层的演出段，默认每段 1 个机位 Scene（到场/换区/离开各一段各一挂）；每个 Scene 可归组 0..N 个 sub。
- **约束**：只在 SubEvent 层存在——Event 直挂本边为违规（体检兜查）；无可用 Scene 时允许暂时缺挂（留缺口，场景化后补挂）。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| detail | 详情 | string | 否 | 归组依据（如"电脑桌前连线翻盘"） |
| sync | 同步 | boolean | 否 | 恒 false（scene 域归组，无级联） |

> `anchored_at → Scene` = 已按子空间证据或用户敲定细分并拍定机位（整点 zone 即整点 Scene 路径）。父 Event 的 occurs_at→Location 恒保留，不受归组影响。
>
> 端点由 Spot 上移到 Scene（读方不需要 realizes 二跳），再由 Event 下沉到 SubEvent（演出段归组）——Spot 仍保留为空间语义层与 3D 布局锚。

#### part_of — 空间从属 `1:N`

- **方向**：`Location → Spot`（父→子）
- **不变式**：每个 Spot 恰好 1 条 part_of 入边；每个 Location 可有 0..N 个 Spot。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 恒 false（空间拓扑边，无级联） |

> **方向已翻转（已实施）**：原方向 `Spot → Location` 与全局「上游→下游」约定相悖（其余包含边 has_section/realizes/has_layer 均父→子），统一翻转为 Location→Spot，边名不变。

#### realizes — Spot 实现场景 `1:N`

- **方向**：`Spot → Scene`（源头→产物，与原 has_scene 同向：边源端从 Location 平移为 Spot）
- **基数**：每个 Scene 恰好 1 条 realizes 入边；1 个 Spot 可 realize 0..N 个 Scene（时段/版本变体各一 Scene）。

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | **恒 false，禁止 true** |

> **级联语义变更（2026-10-09 已拍板）**：原 has_scene 为 sync=true——Location 属性变更会级联作废其全部 Scene。realizes 换源到 Spot 且 sync=false 后该级联通道消失：改 Location 描述不再作废场景美术。理由：Spot 是空间拓扑事实（name/kind/description 基本不变），「Location.description 改一个字 → 全部场景图作废重出」本就是误伤；若未来确需级联，应经 Scene 自身属性而非挂载边。

---

#### has_layer — 场景拥有图层 `1:N`

- **方向**：`Scene → SceneLayer`

| 属性 | 中文 | 类型 | 必填 | 说明 |
|------|------|------|------|------|
| sync | 同步 | boolean | 否 | 默认 `true`（场景更新级联重置图层） |

---

### scene_type 与所需图层

图层按需：并非每个场景都需要全部 4 层。`scene_type` 决定该场景要创建哪些 `layer_type` 的 SceneLayer 节点。该映射表是图层节点创建的依据。

| scene_type | 中文 | 所需图层（layer_type） | 说明 |
|-----------|------|----------------------|------|
| `dialogue` | 对话背景 | `background` | 对话游戏唯一必需层（当前项目 V1 实现） |
| `functional` | 功能场景 | `background`, `floor` | 功能场景加地面层 |
| `combat` | 战斗场景 | `background`, `floor`, `decor`, `mask` | 完整 4 层 |
| `ui` | UI背景 | `background` | UI 背景 |

### 场景美术链

```mermaid
flowchart LR
    subgraph 叙事["叙事基础"]
        Event["Event<br/>事件"]
        SubEvent["SubEvent<br/>演出段"]
        Location["Location<br/>地点"]
    end

    subgraph 场景数据["场景数据"]
        Spot["Spot<br/>空间细分"]
        Scene["Scene<br/>场景"]
    end

    subgraph 场景生产["场景图层"]
        Bg["SceneLayer<br/>background 背景"]
        Floor["SceneLayer<br/>floor 地面"]
        Decor["SceneLayer<br/>decor 陈设"]
        Mask["SceneLayer<br/>mask 遮罩"]
    end

    Event -->|"occurs_at ❌ N:N"| Location
    Event -->|"refines ✅ 1:N"| SubEvent
    SubEvent -.->|"anchored_at ❌ N:N"| Scene
    Location -->|"part_of ❌ 1:N"| Spot
    Spot -->|"realizes ❌ 1:N"| Scene
    Scene -->|"has_layer ✅ 1:N"| Bg
    Scene -.->|"has_layer（functional/combat）"| Floor
    Scene -.->|"has_layer（combat）"| Decor
    Scene -.->|"has_layer（combat）"| Mask
```

> 实线 = dialogue/ui 场景必需的背景层；虚线 = functional/combat 场景按 scene_type 按需添加。

## ID 规则

所有节点使用雪花算法 Base62 编码作为 `id` 属性值（如 `Nv93TkkkgC`），全局唯一，无前缀。由 `.claude/scripts/snowflake_base62.py` 生成。

生成命令：
```bash
python "${CLAUDE_SKILL_DIR}/../../scripts/snowflake_base62.py" -n 1 -q
```

引用已有 Location / Spot 时，通过名称从数据库查询：
```cypher
MATCH (l:Location) WHERE l.name='地点名' RETURN l.id AS id
MATCH (sp:Spot) WHERE sp.name='空间名' RETURN sp.id AS id
```
